# Persistent Graph Memory in Money Trail (Phase 5)

## Overview

Money Trail uses FalkorDB as the authoritative persistent context and memory layer across separate sessions, execution processes, and agent runs. Rather than relying on transient LLM conversation windows or ephemeral memory caches, investigation context is grounded in explicit graph entities and relationships.

## Memory Categories

### 1. Episodic Memory (`memory_type = 'episodic'`)
* Captures specific chronological events, actions, or intermediate observations that occurred during a specific investigation session.
* Links directly to the session that observed it via `(AgentSession)-[:RECORDED]->(Memory)`.
* Retains provenance: tool name, detector rule, and session timestamp.
* Never treated as timeless fact; represents what was observed at a specific time.

### 2. Semantic Memory (`memory_type = 'semantic'`)
* Represents verified, generalized analytical knowledge that remains valid across sessions.
* Bound to explicit dataset and/or investigation scopes.
* Requires evidence grounding via `(Memory)-[:GROUNDED_BY]->(Evidence)`.

## Anti-Poisoning Safeguards

Money Trail enforces strict anti-poisoning guarantees:
1. **No LLM Fabrication As Memory**: Sentences generated by an LLM are never promoted directly to semantic memory without independent verification.
2. **Mandatory Evidence Grounding**: The Memory Curator requires that any factual claim must reference existing `Evidence` nodes in FalkorDB.
3. **Transaction Existence Verification**: Before persisting a semantic memory, the store verifies in FalkorDB that each referenced `Evidence` node points to real `Transaction` records via `[:REFERENCES]`.
4. **Hypothesis Isolation**: Open hypotheses or unverified interpretations remain flagged with `kind='hypothesis'` or unverified status and cannot be promoted to verified semantic facts.

## Identity & Deduplication

Memory IDs are deterministic, canonical hashes generated by `stable_memory_id(scope, scope_id, memory_type, statement, provenance_tool)`:
```text
mem_<sha256(scope:scope_id:memory_type:normalized_statement:provenance)[:24]>
```
Identical claims within the same scope resolve to the same memory node, preventing duplicate node explosion across retries.

## Scope Isolation & Data Integrity

* **Investigation Scope (`scope = 'investigation'`)**: Confined to `investigation_id`. Retrieval queries with this scope strictly exclude memories from other investigations.
* **Dataset Scope (`scope = 'dataset'`)**: Confined to `dataset` namespace. Memories from dataset `ALPHA` will never leak into queries for dataset `BETA`.
* **Bounded Querying**: All memory queries enforce explicit limits (default 50, maximum ceiling 1000) and order by timestamp descending.

## Memory Evolution: Supersession, Retraction, and Contradictions

1. **Non-Destructive Supersession**: When a prior memory is superseded by deeper analysis:
   * The new memory links to the older memory via `(new_memory)-[:SUPERSEDES]->(old_memory)`.
   * The older memory's status transitions to `superseded` and records `updated_at`.
   * Historical provenance of both the old and new memory remains fully inspectable.
2. **Explicit Contradiction Linking**: When conflicting hypotheses or interpretations exist:
   * Bidirectional `(m1)-[:CONTRADICTS]->(m2)` and `(m2)-[:CONTRADICTS]->(m1)` edges are created.
   * Contradicting claims are surfaced explicitly to investigators rather than silently suppressed.
3. **Reactive Revalidation**: If underlying transactions are altered or flagged, `revalidate_memories_for_transactions` queries connected evidence and transitions dependent active memories to `revalidation_needed`.
4. **Invalidation**: Refuted claims transition to `invalidated` status with recorded rationale.

## CLI Usage

```bash
# List memories for an investigation
python -m money_trail.cli memory list --investigation-id inv_demo_1

# Inspect memory details and linked evidence
python -m money_trail.cli memory show mem_1234567890abcdef

# View provenance evidence chain
python -m money_trail.cli memory provenance mem_1234567890abcdef

# View supersession and contradiction history
python -m money_trail.cli memory history mem_1234567890abcdef
```
