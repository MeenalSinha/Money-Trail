## Detailed Narration & Action Walkthrough

### Part 1: The Problem — Financial Laundering Hides in Cycles & Hops (0:00 – 0:45)
* **Screen Display:** Architecture overview diagram showing layered money laundering schemes (circular flow, pass-through mules, fan-in structuring, fan-out dispersal).
* **Presenter Narration:**
  > "Welcome to the demonstration of **Money Trail**, our graph-backed financial investigation agent built for the 2026 FalkorDB Graph Hacks competition.
  > 
  > Modern financial crime rarely happens in isolated transactions. Illicit actors intentionally layer funds across complex webs of shell companies, intermediary mule accounts, and rapid circular transfers to evade legacy relational rule engines.
  > 
  > Traditional SQL databases require expensive multi-table self-joins that grind to a halt after 3 or 4 hops. Anti-money laundering investigators are left with disconnected alert lists and manual spreadsheet stitching.
  > 
  > Money Trail solves this by placing **FalkorDB's graph database** directly at the center of the investigation workflow."

---

### Part 2: Architecture & FalkorDB Graph Core (0:45 – 1:30)
* **Screen Display:** Diagram illustrating FalkorDB schema: `(Account)-[:TRANSFERRED]->(Transaction)-[:TRANSFERRED]->(Account)`, alongside `Investigation`, `Finding`, and `Evidence` provenance nodes.
* **Presenter Narration:**
  > "Money Trail leverages FalkorDB to represent accounts and transactions as a directed, temporal financial graph.
  > 
  > We address **Track 1: Agents That Act on Connected Data**, by equipping our investigation engine with graph-native Cypher detectors that traverse multi-hop flows with sub-millisecond query execution.
  > 
  > And we address **Track 2: Agent Memory and Coordination**, by persisting bi-temporal episodic and semantic memory directly in the graph, orchestrating specialized multi-agent handoffs between Triage and Forensic investigation agents.
  > 
  > Best of all: every single finding generated by an agent is strictly grounded in immutable graph evidence. The agent cannot invent transactions or hallucinate balances."

---

### Part 3: The One-Shot Automated Demo (1:30 – 2:45)
* **Screen Action:** Open terminal, type `money-trail demo`, and press Enter.
* **Presenter Narration:**
  > "To verify that our entire end-to-end pipeline works reproducibly without pre-baked mocks, let's run the built-in walkthrough command: `money-trail demo`.
  > 
  > Watch the terminal output:
  > * In step 1, Money Trail generates a synthetic dataset containing realistic commercial transfers alongside four injected crime topologies: circular cycling, pass-through layering, fan-in structuring, and fan-out dispersal.
  > * In step 2, our dataset contract validator checks schema constraints, timestamp formats, and referential integrity.
  > * In step 3, it connects to a live FalkorDB instance, creates a temporary disposable graph, and ingests all records.
  > * In step 4, the 4-detector investigation engine fires against the live graph, detecting all 6 pattern instances.
  > * In step 5, findings are persisted with explicit anchor links.
  > * And in step 6, Money Trail queries the graph to verify that every single finding is backed by a verified `SUPPORTED_BY` link to an `Evidence` node, pointing directly to a real `Transaction` node.
  > 
  > The entire 6-step cycle completes against live FalkorDB in under half a second."

### Part 5: Multi-Agent Coordination & Persistent Memory (Track 2) (4:30 – 5:30)
* **Screen Action:** Navigate to the **Memory & Coordination** tab.
* **Presenter Narration:**
  > "For Track 2, Money Trail implements robust agent coordination and persistent graph memory.
  > 
  > In complex investigations, a single monolithic agent is error-prone. Money Trail uses a deterministic state machine to coordinate specialized agents:
  > * A **Triage Agent** performs initial anomaly screening and threshold verification.
  > * When high-risk indicators are confirmed, the Triage Agent executes a structured handoff to a **Forensic Specialist Agent**, passing context, hypothesis notes, and evidence references.
  > 
  > Every task transition (`PENDING` $\to$ `IN_PROGRESS` $\to$ `COMPLETED`) is written to FalkorDB, preventing race conditions and ensuring that investigations can be safely interrupted and resumed at any time.
  > 
  > Furthermore, our **Persistent Memory** subsystem indexes investigation insights by entity and tag. If an analyst flags an account in one investigation, that context is recalled when another agent investigates an adjacent cluster weeks later."

## Presenter Reference Notes & Limitations
* **Live LLM vs. Scripted Mode**: If live Anthropic API keys are not supplied in `.env`, the agent seamlessly operates in verified scripted fallback mode, ensuring zero live-demo crashes.
* **Disposable Graph Cleanup**: Remind viewers that `money-trail demo` uses a temporary graph prefix (`money_trail_demo_...`) to guarantee zero interference with existing production or evaluation data.
* **No Fabricated Evidence**: All transactions, accounts, and alerts displayed during the walkthrough are generated by the seeded synthetic generator and stored in FalkorDB; no mocked UI responses are used.
